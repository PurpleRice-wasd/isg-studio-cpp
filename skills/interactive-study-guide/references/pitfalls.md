# 坑清单（都真踩过，每条都花过时间）

编号只是索引，不表示重要性。改引擎/题库/探针前扫一遍对应的那一节。

## 内容 / 数据

1. **JSON 尾逗号** → 那一段题库整段失效，**页面没有任何报错**，那几关的题凭空消失（ch13 的 L5 四道大题就这样丢过一次）。改完题库一定回读校验：临时在页面里 `JSON.parse` 每段 `script[data-bank]` 并打印条数。
2. **数值题只接受一种写法** → 学生写 `1.06 T` 或 `2.51×10⁻⁴` 就被判错，很打击人。用现成的 `parseNum`（支持 `1.06`/`1.06 T`/`2.51e-4`/`2.51×10⁻⁴`/`1,06`），并给每题一个合理 `tol`。
3. **答错只给"错了"** → 等于没反馈。答错要：指出正确项、标出他选的那项错在哪、填数题直接给正确答案、并允许「重做本题」。
4. **题目和讲解脱节** → 用户会问"题目去哪里了"。题必须长在对应小节下面，题区标题写清属于哪一节，并带 `已答/总数`。

## DOM / JS

5. **脚本取不到 DOM**：被 `getElementById` 引用的元素必须排在脚本之前。当年把陪练块从面板里挪到文档末尾后，`#petFig` 变 null → **引擎整段中断、题全没了、依然不报错**。（现在引擎对陪练那几个 id 做了判空、`say()` 会自动变空操作，所以陪练块**可以整块删**；但结算区 `#r-*`、吸顶条 `#s-*` 这些仍是硬引用，照旧别乱搬。）
6. **一个功能崩了拖垮全部**：每个演示/每段可失败逻辑都用 `try{…}catch(e){console.error(…)}` 隔离。ch13 里三个演示都是这么包的，所以演示写坏也不会连累题目和进度条。
7. **`NodeList.forEach`** 在老 iOS Safari（<10.1）不存在。统一写 `Array.prototype.forEach.call(document.querySelectorAll(…), fn)`。
8. **`classList.toggle(cls, force)` 二参形式**（老 Safari 不支持）、`behavior:'smooth'` 的 `scrollTo`（无头环境不推进，校验时看不到效果）——新写的代码用引擎里那个 `setCls(node,cls,on)`。**注意**：老代码里还留着几处二参 `toggle`（卡片/进度/筛选那几段），一直没出问题，就先不动了——新写的别再跟着抄。
9. **`localStorage` 在 `file://` 下可能抛 SecurityError**（Safari），读写全部包 `try/catch`，读失败就用默认值。

## SVG / 图

10. **SVG `<text>` 里不能用 `<sub>/<sup>`**：SVG 不认这两个标签，文字会挤成一行、把版式撑坏。数字下标 `₀₁₂₃` 可以用，字母下标直接写 `μr`。
11. **写死的刻度坐标**：曲线用 `px(r)` 算出来，刻度却写死在 `x=90` → 图和数对不上，"看着挺专业"但读数错位。凡有数据映射，刻度也交给 JS。
12. **中文进 MathJax 的 `\text{}` 会静默消失**（CJK 的字形不在 MathJax 的字体里，缺了就空白）。新页面干脆**不引 MathJax**，公式用 Unicode + `<sub>`（`∮H·dl = ΣI₀`、`B = μ₀μ<sub>r</sub>H`）——离线可用、没有丢字风险、也不依赖 CDN。
13. **宽内容在小屏会溢出**：表格与演示图这类容易横向撑破的容器要加 `overflow-x:auto`（现在是 `.tablewrap` 与 `.demo-fig` 这两个类在管）。

## 交付形态（用户明确否过的）

14. **分文件**（讲解一个文件、练习一个文件）→ 平板上切换麻烦，被否。
15. **顶部标签页切换** → **切页会重置滚动位置**，看到后面去做题再回来就找不着北，被否。要单页长文档、题紧跟讲解。
16. **iOS 上"跳转失败"** → 本质是打开了不跑 JS 的预览器（`<noscript>` 提示条要写清这一点），或用了 file:// 下 localStorage 抛错。加 `<noscript>` + try/catch + 输入框 16px。
17. **引擎里写死章节内容**（关卡名、诊断表的关卡号 `1..5`、建议文案里的"习题 13.6、13.7""《磁介质拆解手册》"、陪练台词里的"演示 1/L0 三道热身题"）→ 换章**不报错，只是显示别章的东西**。两个子代理都被迫手工 grep 七八处。**教训：凡"下一章一定不同"的东西，都要么抽成配置、要么从页面/题库推导。** 现在的引擎：`PAGE` 里只剩存盘 key、收尾文案、图片名、台词覆盖要改；关卡名从题区标题读、诊断遍历实际存在的关卡。**同一类错误还有：把某一章的图片文件名写进 `PAGE.petImages`、把某一章的文件名写进台词。**

## 陪练（形象与交互）

18. **气泡一旦参与文档流就会带着形象乱跑**：形象是 `position:fixed` 的右下角挂件，气泡原来是它的 flex 兄弟；气泡文字一长一短，形象就被挤得左右跳。→ 气泡改 `position:absolute`（`right:calc(100% + 9px)`），位置只由"形象右下角到视口右下角的距离"决定。
19. **`window.innerWidth` 算 fixed 元素的位置会差一个滚动条宽度**（约 15px）：拖动时形象永远比手指偏十几像素，无头校验里还会让「回到右下角」对不上。→ 一律用 `document.documentElement.clientWidth/Height`。
20. **`pointerdown` 里 `preventDefault()` 之后，部分浏览器不再发 `click`**：于是"单击/双击"偶尔失灵。→ 单击/双击自己判（`pointerup` 时看有没有移动 + 300ms 内是不是第二下），别跟原生 `click` 混用（混用会一次点击处理两回）。
21. **`requestAnimationFrame` 在无头浏览器里常常不推进**（标签页切后台也会停），跟随/溜达的补间于是"验不出来"。→ 补间改 `setTimeout(…,16)`，到位自己停；探针就能拿位移当硬指标。
22. **"还没查到"和"确定没有"不是一回事**：形象是异步找的，引擎不能在找完之前就把开关写成「没放图」——脚本和人都会误判（探针就误报过一次）。→ 三态文案：`查图中 / 开·关 / 没放图`，只有候选名全试完才算"没有"。同理，探针要等这个信号，别用固定延时。
23. **点过「回到右下角」后位置记录被清成 null，补间第一帧就 return**：形象再也不动了（跟随/溜达全废）。→ 补间起点用"没有记录就拿元素当前实际位置"（`currentPos()`）。这条是 `pet-probe.js` 抓出来的。
24. **内置形象要嵌成 data URI**：页面可能被复制到任何目录，`assets/` 下的相对路径不靠谱；而 `file://` 下又不能用 `fetch`/XHR 读旁边的文件。→ 图用 `data:image/png;base64` 嵌进引擎，用户自己的台词走 `⟨script src="pet-lines.js"⟩`（脚本标签不受 file:// 的 CORS 限制，`fetch` 受）。
25. **第三方美术要连许可一起进仓库，而且许可要跟着"副本"走**：内置的大肥鱼来自 MIT 仓库，`third-party/dafeiyu-pet/` 里放了原图、许可原文、出处和"我们改了什么"（量化 + 内嵌）。
    ⚠️ 光在仓库里放一份许可**不够**——引擎会被整段复制进每一张生成的页面，页面里嵌着这份美术的 base64，所以**每一份交付物都是副本**。MIT 要求许可原文随所有副本分发，因此 `quiz-engine.js` 里 `FISH` 正上方内联了一份许可原文（改动前实测：生成的页面里出处有、`Permission is hereby granted` 出现 0 次）。那段注释不要当冗余删掉。
    公开分发前想清楚：那套美术本身是同人二创；不想要这个风险就把 `FISH` 的串换掉或置空（置空后引擎不再提供"内置大肥鱼"这个选项，其余照常，那时内联的许可才可以一起去掉）。

50. **菜单开着时形象还在动 → 用户永远点不到菜单**（用户实测报的）：菜单是挂在形象上的绝对定位元素，
    跟随/溜达模式下用户往菜单挪，形象就带着菜单一起挪走。→ 打开菜单时 ① 停掉在跑的补间（`stopGlide()`）、
    ② 跟随/溜达的处理函数都加 `menuOpen` 早退；关掉菜单再恢复。验收用
    `document.elementFromPoint(按钮中心)===该按钮` 当硬指标（只比坐标看不出"被带着跑"）。
51. **菜单固定朝上展开会顶出屏幕**：形象在视口中上部时菜单顶边跑到 y<0（实测 -123），里面的项点不到。
    → 开菜单时按剩余空间决定朝上/朝下，两边都不够就限高滚动；横向贴左时改成向右展开。
    顺手把"模式/大小"改成一行三个（10 个按钮的菜单从 ~463px 压到 ~300px），手机上就不必滚。

52. **移动别用指数衰减插值**（`pos += (goal−pos)×0.16`）：距离一大三四帧就冲完，220px 只要 0.25 秒，
    看着**像瞬移**（用户实测反馈"这个瞬移有点诡异"）。→ 改成**匀速**（按 px/秒 走），"走多久"一眼看得出来；
    跟随鼠标这种"要追人"的才按距离估速度（并设上下限）。
53. **"运动中"要有明确状态**，否则再匀速也像在滑：`.fig` 上加 `.moving` 时换侧面立绘 + 按方向镜像 + 播走路动作。
    两个具体的坑：① 走路动画的**权重**要压过 `.pet.happy .fig.hasimg`（跳一下的类会挂 1.1 秒），
    否则走动时看到的是"跳"；② `moving` 类加在 **`.fig`** 上（侧面立绘那条规则就是这么写的），
    选择器写成 `.pet.moving …` 会静默不生效（两条都真踩过，靠探针量 `animationName` 才发现）。

54. **触摸设备上的"尺寸"规则会被同权重的后定义规则盖掉**：给 `@media (pointer:coarse)` 写的
    `.petmenu button{padding:11px}` 如果放在样式表中段，就会被后面 `.petmenu button{padding:6px}` 压掉——
    实测触摸下菜单项只有 31px、滑块 20px（正是最该大的两个东西）。→ 这类"覆盖型"媒体查询统一放**样式表最末**，
    并在注释里写明原因。
55. **平板 ≠ 放大版的手机**：① 640px 那个断点管不到平板（iPad 竖屏 744~1024px 走桌面布局），
    所以要用 `pointer:coarse` 而不是宽度断点来判断"手指"；② iPad Safari 的 `100vh` 比可见区高 →
    弹出层 `max-height` 要用 `dvh` 兜一层；③ 横竖屏切换 / 分屏改宽度时，开着的弹出层要重新定位
    （`window.addEventListener('resize')` 在老 iOS 上有时不触发，补一个 `orientationchange` + 延时）。
    无头里验触摸：`--blink-settings=primaryPointerType=2,availablePointerTypes=2,primaryHoverType=1,availableHoverTypes=1`
    （2=coarse、1=none），否则 `matchMedia('(pointer:coarse)')` 一直是 false，量的全是鼠标尺寸。

56. **别假设宿主实现了 JS 对话框**：iPad 上用「HTML 查看器」这类 WKWebView App 打开时，
    `window.confirm/alert` 常常没实现（宿主没写 `WKUIDelegate`）→ `confirm()` 永远返回 false，
    表现是"点「清空重来」毫无反应"，而 Safari 里一切正常，所以这个坑只在真机上才暴露。
    → 确认一律做成**页内两步确认**（按钮文字变成"真的清空？再点一次"，4 秒后自动还原）。
57. **`localStorage` 也可能被禁**（`file://` 沙盒 / 隐私模式 / 查看器 App）：读写都包 `try/catch` 之外，
    还要**主动探一次能不能写**并在界面上说明（骨架页在顶栏写「进度无法保存」）——
    否则用户以为进度存上了，下次打开发现全没了，还以为是页面坏了。
58. **别依赖宿主允许重载页面**：`location.reload()` 在沙盒里可能被忽略，「清空重来」改成
    点每张卡自己的「重做本题」逐题复位（这条路径探针反复验过），不依赖任何宿主功能。

59. **"动着抽、停下来还抽"通常是姿态在闪，不是位置在抖**（用户原话："跟随鼠标时大肥鱼会抽搐"）：
    两个来源 —— ① 一停下就把侧面立绘换回正面、一动又换回来（跟随鼠标时"停一下再动"非常频繁）；
    ② 朝向（镜像）按每帧的微小 Δ 翻转，Δ 在 0 附近抖 → 左右翻个不停。
    → 姿态加**迟滞**：到站后先保持走姿 280ms 再回正面；朝向要 |Δ|≥8px 且距上次翻面 ≥350ms 才翻。
    实测：4 秒内的姿态翻转次数从"一直在翻"降到 2 次。
60. **按距离变速会让人觉得"一抽一抽"**：跟随鼠标时距离每帧都在变 → 速度跟着在 90~520 之间变，
    实测抖动比（最快/中位）4.8；改成**固定速度**后降到 1.4。定量验收就用"瞬时速度的 最快/中位 之比"。
61. **速度别按"每帧固定像素"算，要按实际经过的时间算**：`step = speed*0.016` 遇上 `setTimeout` 的真实间隔抖动
    （4~30ms）就会忽快忽慢 → 记下上一次的时间戳，用 `speed*dt`。
62. **凡是"让形象停下"的路径都要复原姿态**：`stopGlide()` 一开始只停了定时器，于是开菜单、切模式、开始拖动
    这些中断路径停下后，侧面立绘一直挂着——切回"原地不动"也**不正身**（用户报的"锁定侧身"）。
    → 把"停"定义成一个动作：停定时器 + 清目标 + `moving=false` + 朝向前后归零；所有停的地方都调它。

63. **别在无头（`--virtual-time-budget`）里量"绝对手感"**：虚拟时间下 `Date.now()` 的推进与定时器节奏是
    **脱钩**的——实测同一个循环里 `speed()` 报 1527px/s，按位置算出来只有 ~400px/s（`dt` 一直被夹到下限）。
    所以"跟随鼠标滞后多少像素"这类结论在无头里不可信。能信的是**相对量**（姿态翻转次数、抖动比、
    到站用时量级）和几何量（尺寸、位置、溢出）。要定"手感"这类参数，要么在真机上调，
    **要么直接把旋钮交给用户**（跟手速度已做成面板滑块，就是这个原因）。

64. **解析数字时"删掉不认识的字符"= 静默改数**（最要命的一类底层 bug，八个代理里这条的含金量最高）：
    `t.replace(/[^0-9eE.+\-]/g,'')` 会把全角负号 `－`(U+FF0D)、印刷体负号 `−`(U+2212)、全角句号 `．` 统统删掉 → 「−5」变 5（**该错判对**）、
    「1．5」变 15（**也判对**）、全角数字「１５」变 NaN（**该对判错**）。中文输入法切全角（Shift+空格）就能打出这些字符。
    → 正确做法是**先归一化**（Unicode 映射表：全角数字/句号、各种负号、间隔号、上标、各种空格 → ASCII），
    再**严格校验**：整串必须是"一个数 + 可选的不含量值的尾巴"，解析不出就返回 NaN。
65. **`parseFloat` 的前缀解析会把算式截断成合法数字**：`5-3` → 5、`1/2` → 1、`2+3` → 2、`5 T=9` → 59（数字被拼起来）、
    `0b10` → 0、`1e` → 1。于是"学生算出来是 2，输入 5-3"会**判对**。→ 校验尾巴里不许再出现数字、不许以运算符开头
    （但单位里的斜杠要放行：`A/m`、`m/s` 是正常单位）。
66. **页面公布的"正确答案"必须自己合格**：`fmt` 曾把答案四舍五入到 3 位小数，而默认容差是 `|ans|×2%`——
    当 `|ans|` 在 0.001~0.025 之间时，**学生照抄提示里的答案仍然判错**，怎么答都过不去。
    → `fmt` 的小数位数按量级给足（`dec = ceil(-log10(a))+3`），保证显示值落在容差内。改动后要写个单测扫一遍。
67. **一个字段写坏不该带走半个页面**：题库里大题漏写 `parts`、选择题漏写 `opts`、或 `lv` 指向不存在的题区，
    原实现会在渲染循环里抛 `TypeError` → IIFE 中断 → 顶部显示 `0/0`、「清空重来」「只看错题」的监听器**根本没装上**
    （点了毫无反应），而题目本身还能答 —— **页面看起来是活的，没人知道坏了**。
    → 逐题 `badReason()` 校验 + 坏题标红跳过（且不计入总题数）+ 每题 `try/catch` + 整轮再包一层。
68. **重复 `id` 会静默双计**：两题共用一个 `store.pts` 键，答其中一道进度 +2、另一道样式永远"未作答"。
    → 渲染时查重并自动改名（`dup-1` → `dup-1-2`）+ 告警。

69. **"弱关列表为空"不等于"各关都达标"**：诊断里 `weak` 只收"该关已答 ≥3 且正确率 <70%"的关，
    于是 `if(done && !weak.length)` 在**答了 1 题**时就成立，结算处会当场宣布"各关都在 70% 以上了"；
    极端情形（每关各错一题）会出现同一屏里评级说"得回去看手册了"、建议却说"很好"的自我打脸。
    → 达标要正向判：**每关已答够（≥3 或该关做完）且正确率 ≥70%**；不够就说"还没到各关达标"。
70. **自动生成的 id 也要参与查重**：大题每一步的 id 是 `<大题id>-<步号>` **自动生成**的，
    只给顶层 `q.id` 查重会漏掉它 —— 题库里另有一道普通题叫 `big1-1` 时：`#s-total` 多算一道、
    点一次作答计两分、两张卡互相覆盖（一张空白却已计入）。
    而且**主探针查不出**：它用 `getElementById` 取卡，撞名时永远只答到第一张，于是照样打印"缺卡=0、进度 50/50"。
71. **筛选/统计要在每次作答后重算**：`lockPoint`/`resetPoint` 只更新卡片与统计，不调 `applyFilter()` ——
    于是"只看错题"开着时，刚答对的那道**还留在错题列表里**，直到用户手动再切一次勾选框。
72. **"清空重来"要连筛选态一起复位**：只清 `store.pts` 的话，若用户开着"只看错题"清空，**一道题都看不见**。
73. **数值题答对后也要回填输入框**：`if(!st.ok) input.value=st.val` 会让答对的题刷新后输入框空白、
    卡面却写着"✓ 答对"（同一次会话里看不出来，只有刷新才暴露）。
74. **关卡名从 `h2` 推导时的两个细节**：计数 span 被拿走后会**留下空括号「（）」**；
    无差别剥开头的「练」会把「练一练 · 13.1 的题」吃成「一练 · 13.1 的题」——只在标题确实以「练」徽标开头时才剥。

75. **兜底代码自己也会崩**：给每道题包了 `try/catch` 之后，catch 里写成
    `brokenCard(lvHosts[q.lv],q,…)` —— 题库里出现一个 `null` 时，`q.lv` **在 catch 里再抛一次**，
    异常逃出循环，整个收尾（筛选/重置/演示/陪练/统计）全不执行。比原来的 bug 更糟。
    → catch 里对 `q` 也要判空；**兜底本身不该再崩**。
76. **题目侧 DOM 也是硬依赖**：`#s-* / #r-* / #onlyWrong / #goWrong / #goAll / #resetAll` 少一个，
    `paintProgress/paintResult` 每次都抛（页面不白屏所以"看着没事"），连带把"陪练对作答说话""只看错题"
    整族行为弄没。→ 统一走 `req(id)`（缺失只 warn 一次并跳过该项），与陪练侧已有的判空保持一致。
77. **找图链不能被"挂住的候选"卡死**：链只靠 `onerror` 前进，某个候选既不 load 也不 error
    （网络盘、大文件）就永远停在那儿；6 秒兜底还直接宣布"没放图"，**后面明明存在的图再也不被试**。
    → 给**每个候选**单独计时，超时就跳过它继续下一个；全局兜底只作为最后保险。
78. **只建一次的 UI 会过期**：菜单只建一次并缓存，而"我放的图片"这一项取决于建菜单那一刻 `hasImg` ——
    用户在图片探测完成前先开过菜单，之后图来了也永远看不到这一项（切不回自己的图）。
    → 依赖状态的项目，开菜单时按状态重建或标记失效。
79. **别用 `Date.now()` 直接比较来判断"过了多久"**：有的 WebView 省电模式会把 `Date.now` 冻住，
    于是 `now-lastAct` 恒为 0 → 溜达永不启动、朝向迟滞永不翻面（都静默）。→ 用 `performance.now()`（单调时钟）兜底。
80. **同一页面加载两份引擎**（复制整段 script 标签的手误）会渲染双份题卡与双份定时器、重复 DOM id，
    而顶部数字仍按第一份算 —— 纯静默。→ 引擎开头用一个 `window.__ISG_ENGINE__` 标记，第二份直接退出。
81. **题库段写在引擎之后会整段消失**（IIFE 只扫一次 DOM）。→ 在 DOM 就绪后再扫一遍，只补新出现的那些并 warn。
82. **自己修的东西要按"正确的那一侧"验**：我修"形象别压住吸顶条"时把 `b`（到视口底边距离，越大越靠上）
    的**下限**当成了上限，等于没修；而且第一版探针只往水平方向拖，根本没测到竖直方向 ——
    两处自我欺骗叠在一起。→ 修完要"按会出错的那个方向"造用例（这次是把指针拖到 y=-9999）。

## 校验工具本身也会坑人

26. **探针正文里出现字面的 script 开/闭标签** → HTML 解析器提前关闭脚本，整段探针变成页面上可见的文字、完全不执行。表现是"标题没变 / 探针好像坏了"。两个子代理都在这里白烧了一轮。→ 用 `assets/inject-probe.py`（自带检查），提到标签时用 ⟨⟩。
27. **手工把 JS 贴进 HTML 忘了包 script 标签** → 同样的症状（JS 变可见文字）。→ 同上，用注入器。
28. **异步的东西不能同步查**：形象/背景是 `new Image()` 的 `onload` 事件（实测要 1~2 秒），固定 600ms 查会误报"没有图/没有背景"。→ 探针里改成**轮询**（`verify-probe.js` 每 250ms 查一次共 40 次，`pet-probe.js` 是 48 次），而且**先等异步定性再测交互**（否则会拿着"还没加载"的状态去拖一个 `display:none` 的形象，报一堆假异常）。
29. **探针查不出叠字与裁切**：SVG 元素越出 `viewBox` 可以用 `getBBox()` 自动查（`demo-probe.js` 已做），但**文字压线、标签挤在一起、形象被裁**只能靠截图。
30. **`for` 循环连续调 msedge 会出现 0 字节输出**（Windows + 新版无头 Edge 上遇到过）→ 一次一条命令。
31. **并发改资产**：如果同时有别的任务在读 `assets/`，你中途重写资产会让它读到前后不一致的版本。→ 要么先等它读完/干完，要么改完再通知；自己读到不一致时**以磁盘最新内容为准**。

## 环境

> 这几条是 Windows + 无头 Edge 环境下的经验，换平台不一定适用；前两条对谁都可能有用。

32. **Windows 控制台是 GBK**：Python 打印中文/✓ 会 `UnicodeEncodeError`（看起来像脚本崩了）。结果写文件再读。
33. **`rm -rf` 通配符**在共享临时目录会被安全策略拦下 → 逐个列文件名删除。
34. **无头 Edge**：输出文件要写 `%TEMP%` 的绝对 Windows 路径、每次独立 `--user-data-dir`（也避开上一轮的 localStorage）、URL 里带 `#anchor` 不会滚动定位。
35. **探针脚本**：**不可靠的是 `load` 事件和长链回调**（`setTimeout` 在 `--virtual-time-budget` 下是会跑的，引擎的补间也靠它）→ 结果写 `document.title`，同步能拿到的就同步写，异步的用轮询补；探针页要放在目标目录（相对路径图片才认得到）；别在探针里写含 `\n` 的正则。
36. **交付形态就是本地 HTML**：不要依赖任何在线发布/预览服务（有些环境根本不让发布，
    而且一旦发布出去，页面里的用户图片和课件内容就跟着走了）。写完给路径，让用户自己打开。
37. **assets 与骨架页内联副本会走散**：骨架页把引擎/CSS 内联在里面（单文件交付要用），两份一起改很容易漏一边，症状是"改了资产，新章还是老引擎"。→ 改完跑 `assets/sync-skeleton.py`（默认只检查、报第一处差异；`--write` 才写）。反过来（改的是跑通的章节页）用 `refresh-assets.py`。
38. **用 shell heredoc 往文件里灌含反斜杠的代码会被吃掉一层转义**：`split(/\r?\n/)` 会被写成真的换行，整段 JS 语法错误。→ 这类补丁写成 `.py` 文件再跑，别塞 heredoc。

## 陪练 · 第二轮（8 个子代理查出来的，2026-10-16）

39. **绝对定位的气泡在"零宽包含块"里会塌掉**：`.pet` 是 `position:fixed`、宽度收缩到形象那么宽（76px），
    气泡 `right:calc(100% + 9px)` 的可用宽度算出来是**负数** → 落到 min-content，整句话排成每行两三个字的
    细长条（实测宽 41~55px），长台词还会顶出视口上沿且没有滚动条。→ `width:max-content` + `max-width` +
    `max-height` + `overflow:auto`，并且给老浏览器补一条 `width:230px`（不支持 `max-content` 时别塌）。
    **这条是"把 flex 兄弟改成绝对定位"时引入的回归，探针查不出来，只有量尺寸/截图才发现。**
40. **改尺寸之后要重新夹位置**：`applySize()` 只改 `--petk`，形象贴着左/上边时放大 25% 会越界 18~24px
    （left=-10 / top=-16），而 resize 那条路径会重夹——两条路径不一致。→ 尺寸变化后补 `reflow()`。
41. **两条并发探测链会互相覆盖**：头像链与背景链同时 `new Image()`，头像链回调里无条件 `paintBg(u)`，
    谁后到谁赢（实测总是头像赢）→ `PAGE.bgImages` 成了死配置。→ 用 `bgDone` 标志 + 专用背景图 `force` 优先。
42. **`resolveArt()` 挂在 IIFE 末尾，一抛就把 `paintProgress()` 带走**：页面没有 `#petFig` 时
    `fig.innerHTML=''` 抛 TypeError，**顶部进度变成「已作答 0/0」、结算区空白、用户看不到任何报错**。
    两条触发路径：删掉陪练块但存盘里选着内置大肥鱼；删掉/挪走陪练块但同目录有图（异步 onload 里走到）。
    → `resolveArt()` 开头判空 + 收尾整段包 `try/catch`。
43. **"还没有陪练块"时顶部开关会变成死键**，文案还一直写着「开」或卡在「查图中」。
    → `HAS_PET` 为假时把开关 `display:none` 藏起来。同理：找图卡住（既不 load 也不 error）要有超时兜底，
    否则永远停在「查图中」。
44. **资源加载失败会混进"脚本错误"**：`window.addEventListener('error',…,true)` 连图片 404 一起收，
    记成 `?@0`，于是验收清单的「脚本错误=无」误报。→ 收集器里只收 `e.message` 存在的（真 ErrorEvent）。
45. **同步读错误集读不到异步抛的错**：图片 `onload` 回调里抛的 TypeError，同步段查不出来，
    页面会"验收全绿但其实报错了"。→ 异步轮询结束时**再报一次**错误集（`异步脚本错误=`）。
46. **演示 JS 必须写在引擎脚本内部**（`fmt()` / `el()` / `say()` / `LINES` 都是闭包里的）：
    写到外面单独的 `⟨script⟩` 里会 `ReferenceError`，还被演示自己的 `try/catch` 吃掉 → **演示静默不显示**。
    位置就是骨架页里那段「章专用演示：把本章的演示 IIFE 放在这里」。
47. **`prefers-reduced-motion` 那条 CSS 会被权重压掉**：媒体查询里写 `.pet .fig{animation:none}`（0,2,0）
    压不过 `.pet .fig.hasimg{…animation:bob}`（0,3,0）与 `.pet.happy .fig.hasimg`（0,4,0）→ 死代码。
    → 媒体查询里把选择器写到同样权重（`.pet .fig.hasimg`）。
48. **长按陪练要屏蔽系统菜单**：iOS 长按图片会弹「存储图像/拷贝」，和"长按开菜单"打架 → `-webkit-touch-callout:none`；
    双击还要防页面缩放 → `touch-action:none`（只加在形象上，页面别处照常能滚）。
49. **安卓与 iOS 的兼容清单**（两端的坑不一样，都要过）：
    `-webkit-text-size-adjust:100%`（安卓字号自动放大）、`-webkit-tap-highlight-color:transparent`（点按闪块）、
    字体栈要带安卓中文字体名、安全区 `env(safe-area-inset-*)`（吸顶条/底部留白/陪练位置）、
    窄屏把整屏 `blur()` 调轻（低端安卓 GPU 弱）。

## 引擎与校验（2026-10-16，做桌面工作台时发现的）

50. **题库被整份渲染两遍——题卡翻倍、顶部总数翻倍，而探针查不出来**：引擎首扫 `script[data-bank]`
    时**没给那个 script 打"已读过"标记**，于是 `DOMContentLoaded` 时 `scanNewBanks()`
    （它本来是给"题库段误放在引擎之后"补渲染用的）把同一批题库**又渲染了一遍**。
    骨架页 2 道样例题一度变成 **4 张卡、顶栏写着 `0/4`**，而页面外观完全正常。
    **十一项必查为什么漏掉了它**：探针插在 `</body>` 前，赶在 `DOMContentLoaded` **之前**执行，
    那一刻页面里只有一份，`题库条目=2 / 顶部进度=2/2` 看着全对；DOM 转储与截图是在 load 之后取的，
    才看得到翻倍。修法：首扫里加 `s.__isgSeen=1;`（`scanNewBanks()` 本来就靠这个标记跳过）。
    **验收要补一条**：load 之后读一次 `#s-total`，与题库里的作答点数对一遍
    （`apps/isg-studio` 的校验 runner 已把这条做成常驻校验项「顶栏总数」）。
51. **`#s-total` 只看作答点，不看题卡**：`.cnt` 与 `#s-total` 的分母都是**作答点**
    （一道大题按 `parts` 数算），而页面上的 `.q` 是**一道大题一张卡**。含大题的关卡上两者天然不等
    （2 道大题 / 6 个 part → `.cnt` 是 `6/6`、`.q` 只有 2 张）。
    拿"题卡数"去核对 `.cnt` 会**误报**成"计数对不上"——校验器要比的是作答点数。
52. **`grep -c` 与 heredoc 的老问题又踩了一次**：往 HTML 里注入的 JS 字符串用 shell heredoc 写，
    ` ` 这类转义会被吃掉一层，写成**真的 U+2028 字符**，正则直接语法错误（`Invalid regular expression: missing /`）。
    写法：补丁写成 `.py` 文件再跑，或者用 `chr(92)` 拼反斜杠，别在 heredoc 里数反斜杠。

## 多来源（2026-10-16）

53. **自创题型名（`judge` / `fill` / `short` …）→ 引擎只认四种**：题库的 `type` 只认
    `single` / `multi` / `num` / `big`（SKEL L1799、契约 `§1.4.8`）。模型从真题里顺手带出来的
    "判断题 / 填空题 / 简答题"这类名字**不被认识**：它会被**降级成单选**（`bank.js` 的 `normalizePart`
    有一条"type 不认识，已按 single 处理"的修正），选项与答案的语义跟着错位——一道填空变成
    "从 2–6 个选项里选一个"，**而页面不报错**：题还能答、还能判分，判的却不是你要的那个东西。
    （独立的 skill 引擎更钝：它直接把这类题**标红跳过**、不计入总题数——两种表现都不该出现。）
    → 从真题提炼题型时就先**映射**：判断题 → 两个选项（正确/错误）的 `single`；填空（词/短语）→
    `num`+`ansText` 或 `single`；填空（数值）→ `num`；简答/计算/证明 → `big`+`parts`；
    作图/读图不新增题型，归入 `big` 的 `single` 步或交给演示。出题提示词里要把四种题型名与这张映射表**明写**
    （app 侧现在是 `questionTypeBlock()` 在渲染真题的题型规律）。
54. **把扫描件当文本用 → 抽出来是空的**：整页都是图片的 PDF（扫描件）没有文字层，抽取结果一个字都没有。
    **本工具这一轮不做 OCR**，所以这件事必须在**导入时**就说清楚——"请自行转成可选中文字的 PDF，
    或导出成 `.md`/`.txt`"——**不要等生成失败才报错**：用户已经等了几分钟，还会以为是模型或页面的问题。
    代码里那条"这个文件里一个字都没抽出来"的兜底是**最后一道闸**，不是提示方式。
55. **`editedPages` 必须带来源前缀，否则多来源时同页号互相覆盖**：用户在"抽取预览"里改过的页是按
    `index` 回填的，而**多份来源的页号都从 0 开始**——不带来源前缀时，来源 A 的第 3 页修订会被
    来源 B 的第 3 页修订顶掉（谁后写谁赢），或干脆盖到另一份材料上。
    症状是**静默串页**：生成的正文里出现的是另一份材料的句子，处处不报错，只有人去对照原文才发现。
    → 修订条目一律带来源 id（如 `{sourceId, index, text}`，键用 `sourceId + '#' + index`），
    回填时按来源分别应用；页面与日志里也按来源分开显示，别只给一个裸页号。

## 一册多章 · 累积成一册（2026-10-16）

83. **两章各自从 0 编关卡号 → 第一章的题渲进第二章的题区**（`lv` 的三处必须同源）：
    `lv` 这个数是**三处共用**的同一个键——① 正文里题区宿主 `.qlist[data-lv=N]` 与计数 `.cnt[data-cnt=N]`；
    ② 题库 JSON 里**每道题**的 `lv`；③ **引擎运行期**按 `data-lv` 建的分桶（`quiz-engine.js` 遍历
    `document.querySelectorAll('.qlist')` 建 `lvHosts`，题是按 `lvHosts[q.lv]` 取宿主的）。
    合并两章时若各按"章内下标"编号，两章的第一个单元都拿到 0 → 第一章的题全被塞进第二章的题区，
    **而页面不报错**：题卡还在、还能判分，只是长在了别人的讲解下面（结算区里的关卡名也跟着错，
    除非题区带了 `data-name`）。→ 整册拉平成一个槽位表，`lv` = 全册槽位下标；拼装完再断言
    `data-lv` 恰好是 `0..N-1` 各一次（拼装器第 9 步就是这么挡的）。

84. **给所有章一律加 id 前缀 → 每再合并一章就要把全册进度搬一次家**，而搬家的失败模式是**完全静默的串档**：
    作答点 id 就是**存盘键**（引擎把进度按 `store.pts[q.id]` 存在 `localStorage[PAGE.key]` 下，QE§1）。
    给已经发出去的章改名，旧记录还躺在 localStorage 里，只是没有任何一道题再引用它——界面表现是
    "这一章进度清零"，中间一条报错都没有。更糟的是"搬家"（按老键读出来、按新键写回去）：
    它要求新旧 id 的对应关系一字不差，错一个就是把 A 题的答案记到 B 题上（症状同样是静默的——
    学生看到一道没做过的题写着"已答对"）。→ 正确做法是"**不撞不改**"：带过来的章标成 `frozen`、id 一个字不动；
    新章先按自己的原命名走，**只有与已登记的 id 真撞车**才改用 `c<章序>-` 前缀。
    于是最常见的"在已有册子上再加一章"零改名、零搬家。配套的一条：冻结章要**先占 id 与锚点**，
    否则"新章排在旧章前面"时被挤去改名的反倒是冻结章——一样是静默的。

85. **从成品页反推的两个已知盲区**（`pipeline/revive.js` 的分辨率上限，两边都不该报错）：
    ① **单元导语 vs 模型自己写在正文里的导语**：拼装器把 `u.lede` 单独渲染成 `<h2>` 后的
    `<p class="lede">…</p>`；模型写的正文第一句如果也是 `<p class="lede">…</p>`，两者在成品页里
    **长得一模一样、分不出来**。症状是合并后那一段导语**重复一次**（题区导语 `quizLede` 缺省取讲解那一段，
    所以"题区导语与讲解导语一致"时也无从判断它原本是显式写的还是兜底来的）。
    ② **演示 DOM 原本挂在正文第几行已无从还原**：`<!--DEMO:id-->` 占位注释是被**就地替换**的，
    替换后的 DOM 与"模型直接写在正文里的演示"在成品页里同样分不出来。→ 做法是让它**留在原地**
    （`lectureHtml` 里不动）、`markup` 记成空串、只把 JS 收进 `demos[]`：位置不变、内容不丢；
    硬抠出来反而再也不知道该塞回哪一行。这两条是反推这条路的能力上限，不是文件坏了。

86. **进度跨 origin 不通**（用户会把这件事当成 bug 报回来）：
    做题进度在浏览器本地的 `localStorage[PAGE.key]` 下。应用内预览走 `isg://local`、双击文件走 `file://`、
    起个本地服务器看走 `http://localhost` —— **三种 origin 各自一份 localStorage，互不相通**，
    这是同源策略，**任何脚本都搬不过去**（不是页面少写了一段同步代码）。
    另外 `file://` 在 Chromium 里是 **opaque origin**：`localStorage` 可能直接抛 SecurityError，
    引擎自己就会走"存不住"的降级路径（顶栏写「进度无法保存」，见 `pit 57`）。
    → **不许承诺"进度一定在"**：界面与文案要如实说"换一种打开方式看不到之前的进度"。
    合并成一册只能保证**存盘键不变**（老章的记录还认它自己那些题），保证不了"换个入口还能看见"。

87. **两章的正文里各自写出同名 `<h3 id>` → 全页 id 自检当场判失败，用户什么也拿不到**：
    契约要求讲解正文的 `<h3>` 上带一个稳定 id（形如 `id="k1311"`），题库的「回看」链接按它找。
    这些 id 是**章内自洽**的——跨章没有任何机制区分。而"按章内第几个单元第几个知识块编号"
    是同一套提示词下最自然的写法，于是两章很容易都写出 `k1311`。
    不处理的话：拼装末尾的全页 id 自检会**判定失败**（那是对的，宁可不发也不发一份坏页），
    但用户拿到的是一句"页面上有重复的 id"，他做不了任何事，只能换模型重跑。
    → 做法与「单元锚点」「演示 id」**完全同源**：**不撞不改**，按 `processOrder`（冻结章先占）走，
    让新章改名成 `c<章序>-真实id`，并且**正文里的 `href="#…"` 与题库里的 `ref.h` 都要跟着改**——
    只改 id 不改链接，那些链接会指到前一章的同名锚点上（点一下跳到别章，没有任何报错）；
    只改正文不改题库，那几条 ref 会被死链检查**静默摘掉**（学员觉得"这题怎么没有回看"）。
    ⚠️ 只在**多章**时做：单章时章内重名是模型自己写错了，那种错值得当场炸出来，不该被悄悄抹平。

88. **产出形态（`book` / `separate`）必须在 `createJob` 那一层落地**：
    只在 IPC 里设 `job.mode` 的话，直连 `createJob` 的调用点（测试、第三方脚本）拿到的是 `undefined`，
    而它在流水线里会**静默按 `book` 走**——"我要每章分开生成"变成"给我一份合订本"，没有任何提示。
    这与 `normalizeSources` 必须放在 `createJob` 是同一条教训（`test/e2e-mock.js` 正是不走 IPC 的那种调用）。
    → 凡是**决定产出形态**的入参，都要在最靠近任务创建的那一层落地，并在认不出时报错而不是挑一个默认值。

89. **章号有两个字段名：规划侧的 `chapter.no` 与拼装侧的 `chapter.number`**：
    `outline.chapter.no` 是规划阶段自己算出来的，而喂给拼装器的 `chapters[].chapter` 用的是 `number`
    （拼装契约如此）。文件名生成（`outName` / `bookOutName`）如果只读其中一个，
    另一个形状进来时读到 `undefined`，文件名就**静默**少掉 `ch13-` 那一段前缀——
    产出照常、页面照常，只是叫「磁介质-讲练一体.html」而不是「ch13-磁介质-讲练一体.html」，
    用户按名字归档时才会发现它排不到一起。→ 两处都认（`chapterNoOf`），别赌调用方给的是哪一种。
