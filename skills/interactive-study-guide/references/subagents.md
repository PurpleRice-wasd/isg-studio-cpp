# 内置子代理：出题 + 审题 + 来源分析（出题/审题在一章 ≥40 个作答点时默认启用）

## 为什么开、为什么只开两个

- **省主上下文**：题库是一章里字数最多的东西（60–75 个作答点）。让子代理去写、**主模型不把题库全文读进上下文**，
  主上下文只留「单元划分 + 题目 id 清单 + 审题报告」。省下来的是主会话每次调用都要重读的那部分。
- **交叉检验**：探针只验得了"判分逻辑对不对"，**验不了"答案本身对不对"**。数值题答案错一位，学生就照着学错——
  这是这套材料里最贵的一类错。审题代理**独立重算**，才拦得住。
- **只开两个**：子代理是开销大头（实测：13 个子代理 = 2310 次模型调用、2.65 亿 raw token，占整轮 32%）。
  两个是"写 + 校"的最小闭环，再多人就是重复劳动。
  （**来源分析（代理人 C）不算在这里**：它是**每份来源各一次**的独立调用，不是"写 + 校"闭环的一环，
  也不与这两者共用上下文——见文末。）
- **别指望子代理本身省钱**：它省的是主上下文，不是总账。**真正的省钱开关是下面的"素材落盘"**——
  素材落盘 + 子代理只按文件读，两边上下文都小；把素材复述进子代理的 prompt 等于把它在主上下文里再存一遍，反而更贵。

## 第 0 步（省 token 的关键）：主模型先把素材落盘

派代理之前，主模型自己做两件小事，落到临时目录（建议 `_work/`，收尾时删）：

1. `_work/units.md`——**单元划分 + 术语表**：
   - 5–7 个单元，每个写：标题、覆盖哪些课件页/小节、讲解要点 3–5 条、预估作答点数；
   - 一张**术语表**（本章符号、译名、单位写法），两个代理都要照它写，这是防止"五个人的手笔"的唯一办法。
2. `_work/source/<unit>.md`——每个单元对应的**素材摘录**：从 PDF / 手册里抽出的那一块，
   含公式、常数与数字。**只抽这一块**，不要把整章粘进去。

然后让子代理**去读这些文件**，不要把素材复述进 prompt。

## 代理人 A：出题

一次覆盖全章，或按单元分批（每批 2–3 个单元）。提示骨架（照抄改）：

> 你是这套「讲练一体」材料的**出题人**。只产出题库 JSON，**不写讲解、不碰页面**。
>
> 必读（按顺序）：
> - `skills/interactive-study-guide/references/quiz-engine.md`（字段与判分规则，尤其 1.5 节的题库校验）
> - `_work/units.md`（单元划分与术语表）
> - `_work/source/<unit>.md`（这部分素材；**只许用这里出现过的概念、常数与数字**）
>
> 硬约束：
> - 术语表里的译名 / 符号 / 单位写法一律照用，不要另起写法。
> - 每单元 6–8 个作答点；**概念题 : 计算题 ≈ 1:1**；全章综合大题放在最大 `lv`，**一步一问**。
> - 每题必须有 `hint`（只给方向、不给答案），以及 `sol` 或选项级 `why`（写清"它错在哪"，不是只说"错"）。
> - 数值题必须给 `tol`，按素材的真实精度定（别一律 2%）；`ans` 必须是数字（`2.51×10⁻⁴` 要写成 `2.51e-4`）。
> - **每个数值答案先自己手算一遍**，算式写进 `sol`；有效位数与素材一致。
> - **讲练对应**：每道题只考它上面那一节讲过的东西，别考后面才出现的结论。
> - `id` 全局唯一，且别撞大题的自动步号（`<大题id>-<步号>`）。
>
> 产出：用 Python 生成 `_work/bank/lv<N>.json`（`json.dumps(ensure_ascii=False)` 生成 + `json.loads` 回读校验，
> 一句一题、别手写转义）。
> 回复里**只报**：每个 `lv` 的作答点数与题型配比、以及**你自己没把握的题目 id 清单**（供审题代理重点看）。
> 不要把题库全文贴在回复里。

## 代理人 B：审题（独立重算，不看 A 的结论）

**关键**：B 拿到的是「题干 + 素材」，**不是** A 的推导过程。B 必须自己算，然后比对——
看了别人的解法再"验算"会顺着对方的错误走，那不是交叉检验。

> 你是**校对**。任务是独立核验这份题库，**尤其是数值答案**。不要照抄原作者的解法。
>
> 必读：`_work/source/*.md`（素材）、`_work/bank/*.json`（待审题库）、`_work/units.md`（术语表）
>
> 逐题按这个顺序核验：
> 1. **重算**：从题干独立算出答案（用素材里的常数与公式）。与 `ans` 不符 → 报「答案错 / 题干缺条件」。
> 2. **量级与单位**：答案的数量级是否合理（拿 `sol` 里的算式反推一遍），`unit` 与算式是否自洽。
> 3. **容差 `tol`**：与该题应有的精度匹配吗（太松会把错答判对、太紧会把对答判错；`ans=0` 时尤其注意）。
> 4. **干扰项**：每个 `ok:false` 的选项是否**真的是错的**、`why` 给的错因是否成立
>    （有选项其实也说得通 → 高危，必须报）。
> 5. **唯一性**：有没有两个选项都成立、或答案不唯一（数值题是不是漏了"取哪个根/哪种情况"）。
> 6. **重复与越界**：同章内有没有实质重复的题；有没有考到本单元之外、或课件里根本没讲的内容。
> 7. **讲练对应**：每题考的点，是否在它上面那一节里讲过（对照 `_work/units.md`）。
>
> 产出：一张清单，每条写：`题号 | 判据(1–7) | 期望 | 实际 | 证据(算式或引用) | 严重度`。
> **没把握的写"存疑"，不要猜**。你只报问题，**改题由出题人做**。
> 回复里只给清单与统计（多少题核过、几条问题），不要重复贴题库。

## 主模型拿到两边之后

1. **只把 B 的清单读进来**（不要读题库全文），逐条裁定：改 / 退回给 A 改 / 判定 B 误报（要写理由）。
2. 需要改的题交回 A，改完**再审一遍涉及的那几条**（只审改动项，不重跑全量）。
3. 之后才进 SKILL.md 的第 5 步（拼页）。拼页后照常跑探针——
   **探针验"判分逻辑"，B 验"答案正确性"，两者互补，缺一不可。**

## 不交给子代理的事

- **拼页**（讲解块、题区位置、演示插入点）：要整章的全局观，主模型自己做。
- **探针校验与截图**：脚本 + 命令行无头浏览器，主模型自己跑（交给子代理等于把同一份页面上下文再存一遍）。
- **最终通读**：讲解与题的衔接、难度曲线、术语是否统一，只有看过全章的人能判。

## 成本与风险

| 风险 | 对策 |
|---|---|
| 两个代理把全章素材读一遍 → 白省 | 只给各自那一块：A 按单元读 `_work/source/<unit>.md`；B 只读题库与素材，不读页面 |
| 风格漂移（两人术语不一致） | 术语表是硬约束；主模型拼页前统一润色一遍术语与量词 |
| 子代理自信地报错答案 | 审题必须**独立重算**，且每条要给算式或引用；"存疑"允许、"猜"不允许 |
| 两个代理同时写同一文件 | B 只读题库、只写报告；所有改动都回到 A（或主模型）手里落地 |
| 代理漏题（少写/跳号） | 主模型在拼页前核对「`lv` 分布与作答点总数」是否落在 60–75 的区间，缺了就退回补 |
| 交付时忘了清临时件 | `_work/` 属于收尾要删的临时件（除非用户要求保留以便续做） |

## 代理人 C：来源分析（每份来源各开一次，互不可见）

一章可以同时用**课件 / 课本 / 习题 / 历年真题**四类材料，每类可以给多份。
**每一份来源各开一次 C**（不是"一次分析所有来源"），产物是一份 `sourceNote`——
后面每一步（切单元、写正文、出题、审题）看到的是这些结论，而不是几份材料的原文堆在一起。

**职责**：把**这一份**材料读懂、读薄。提取它的结构（`outline`）、术语（`terms`）、公式（`formulas`）、
常数（`constants`）、以及**角色专属**的东西：真题的题型规律（`questionTypes`）、
自己没看懂的地方（`warnings`）。**它不是出题人，也不写讲解**——只产出"对这份材料的理解"。

**输入（只有这一份来源）**：
- 这一份材料的正文（`pages`；课本被 `scope` 限成一节时是 `scopedPages`）；
- 它的角色（`courseware` / `textbook` / `exercises` / `exampaper`）与用户指定的范围（`scope.label`）。

**输出**：一份 `sourceNote`（字段表见契约 `§6.4`）——`{sourceId, role, summary, outline, terms, formulas,
constants, questionTypes, warnings}`。`sourceId` / `role` 原样回填，后面靠它对回到是哪份材料。

**隔离要求（这条是重点）**：
- **不喂别的来源**：C 看不到其他来源的正文，也看不到其他来源的 `sourceNote`。
  多份材料必须被**各自独立**理解一遍，融合时才是"几个视角"；
  把第一份的结论喂给第二份，等于让每份材料都顺着同一个说法走，融合就白做了。
- **不喂任何过程痕迹**：不喂单元划分、不喂已生成的讲解或题目、不喂任何人的思路——
  与代理人 B 是同一条隔离原则（看了别人的东西再"分析"会顺着它走）。
- 各来源之间**不互相校验**：拿不准的写进 `warnings`，不要用另一份材料去"纠正"这一份——
  两份材料本来就可能说法不同，那是要留给融合那一步处理的信息，不是 C 该消解的。

**两条角色专属的硬规矩**：
- **`exampaper` 只输出题型规律，不得粘贴原题**。要的是"这份卷子由哪些题型构成、各占多少题/多少分、
  考法是直接套公式还是两步计算、哪些考法反复出现"，**不是**某一道题长什么样。
  工程上真题正文的**原文权重是 0**——**原文根本不进提示词**，想抄也无从抄起。
  每条规律都要给出它对应到四种题型的哪一种（`mapped` 只能取 `single`/`multi`/`num`/`big`，
  映射表见契约 `§1.4.8`），**不许自创 `judge`/`fill`/`short`**：引擎不认识，会被降级成单选、答案语义错位（pit 53）。
- **`textbook` 只看指定的一章/一节**：用户给了 `scope` 就只分析那一节，
  其余部分不在本次范围内、也不要顺手分析。整本课本一次分析既超上下文，又会把"这一章"稀释掉。

**在 isg-studio 里**：这一次分析 **= 一次独立的 API 调用**——**没有文件系统**、没有子代理、没有无头浏览器。
所以 C 的产物必须**当场以 JSON 返回**，不要写"已保存到 `_work/…`"、也不要写"我先读一下这份文件"。
提示词由应用侧装配（`apps/isg-studio/src/main/pipeline/prompts.js` 的 S0 段），产出直接进内存；
单来源时这条路会退化成"只有一份课件"，与从前的行为逐字节一致。
