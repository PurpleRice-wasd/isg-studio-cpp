# 可交互讲练一体学习页

给一章内容做一份**本地 HTML**：左边（上面）是讲解，**每个小节讲完紧跟着这一节的题**，题点下去就判分并逐项讲错在哪；关键概念配可拖滑块的演示；全部小节之后放综合大题与学习结算。做完让用户双击用浏览器打开。

## 一、形态铁律（用户已经用血泪教训定下来的）

1. **单页长文档，不要标签页、不要分文件。** 用户否掉过"顶部切换讲解/练习"的方案：**切页会重置滚动位置**，看到后面再去做题就找不回原处。所以题必须长在对应小节下面，滚下去就能做。
2. **讲—练紧邻**：一个知识块（或一节）讲完，紧接着就是它的 2–4 道题；题区标题写成「练一练 · 13.1 的题」，带 `已答/总数`。
3. **综合题放最后**：3–4 道把整章串起来的大题，**拆成"一步一问"**（每小步单独判分），在最末，之后是「学习结算」。
4. **即时反馈**：点选项/填数值立刻判定；正确项着绿、选错的那项着红，并**逐项写出"它错在哪"**；写不出来先给「思路提示」（只给方向），解析默认收起、答题后展开。
5. **进度自己会存**：用 `localStorage`（key 带章号），顶部吸顶条常驻 `已作答 x/N · 正确率 · 错题`，可切「只看错题」，每题可「重做本题」。
6. **题目数量参考**：一章 60–75 个作答点比较合适（概念题 25 左右、计算题 25 左右、综合大题 20 左右）。
7. **陪练有形象才出现**：同目录没图、也没选内置形象时，右下角**必须空无一物**（占位 0px），
   **不许退回一个内置的简笔画小人**（用户明确否过那个）。形象只有"用户的图 / 内置大肥鱼"两条路，见第五节。

## 二、工作流程

1. **先定内容来源（可以多份）**：一次可以同时用**课件、课本、习题、历年真题**四类材料，每类都可以给多份。
   它们分工不同：**课件**定主线（这一章怎么切、讲到什么深度），**课本**给定义与推导的权威版本，
   **习题**提供练法与易错点，**历年真题只用来定题型形态**。优先用同章已有的《拆解手册》类文件；
   没有就按课件/教材抽知识点骨架。
   **扫描件这轮不做 OCR**：整页图片的 PDF 没有文字层，抽出来是空的——**导入时**就要请用户
   自己转成可选中文字的 PDF、或导出成 `.md`/`.txt`，别等生成失败才说。
   **PDF 抽文本要先回读校对**：CJK 常见缺字形（某几个字变空白）、公式常被排成图片（抽出来是乱码）、
   多栏版式会串行——抽完随手翻两页对照原文件，别直接拿去写讲解。

   **1.5 每份来源各起一次独立分析（互不可见）**：给每份材料**单独**开一次分析，产物是一份 `sourceNote`
   （摘要 / 结构 / 术语 / 公式 / 常数 / 题型规律 / 存疑）。这一次只看**这一份**材料，
   **不喂别的来源的结论、也不喂任何出题过程的痕迹**——每份材料被独立理解一遍，融合时才有互不污染的视角
   （与审题代理的隔离原则是同一条，见 `references/subagents.md` 代理人 C）。两条要写死：
   - **真题只提炼题型规律，绝不摘抄原题**（工程上真题正文根本不进提示词，原文权重为 0）；
     提炼出的题型必须**映射**到四种题型，映射表见契约 `§1.4.8`。
   - **课本只看用户指定的那一章/一节**（`scope`），不整本分析——整本既超上下文、又会把这一章稀释掉。
2. **切"讲—练"单元**：把一章切成 5–7 个单元（如 概念 / 核心推导 / 例题习题 / 专题 / 综合）。每个单元：讲解块 + 紧跟的题区。给每级题区分配一个 `lv`（0…n），综合大题放最大编号。
   **把单元划分与术语表落到 `_work/units.md`**（术语表是后面不让多人手笔打架的唯一办法）。
3. **写题库**：若干 `<script data-bank id="bankN" type="application/json">[…]</script>`，一段一个单元的题。字段见 `references/quiz-engine.md`。**写完必须检查 JSON 合法性**（尾逗号会让整段静默失效，页面不报错、题凭空消失）。
   **题目形态要贴合真题题型，并映射到四种题型**（判断题→`single`、填空→`num`+`ansText` 或 `single`、简答/计算/证明→`big`+`parts`；**不许自创 `judge`/`fill`/`short` 这类名字**）——见契约 `§1.4.8`。
   **一章 ≥40 个作答点时，默认开两个子代理来做这一步**（一个出题、一个独立审题），
   规矩与可直接照抄的提示骨架见 `references/subagents.md`：
   主模型先把素材按单元落盘（`_work/source/<unit>.md`），两个代理**按文件读**、产物也落盘（`_work/bank/lv*.json`），
   主上下文只留「单元划分 + 题目 id 清单 + 审题报告」——**不要把题库全文读进主上下文**，那等于白开代理。
4. **写演示（2–3 个）**：挑"学生最容易想歪、最适合用拖拽建立直觉"的量（ch13 是 μ_r、同轴电缆分区、磁滞回线）。写法见 `assets/demos-example.js`。**读数与曲线都要由公式现场算出来画**，别贴图，这样图和数永远自洽。
5. **拼页面**：以`assets/page-skeleton.html`为起点（骨架已实测可跑），把讲解块换成这一章的小节，把题区插到各单元末尾，把演示插到对应知识点旁。合并已有手册的成套做法（含脚本）见 `references/build-and-verify.md`。

   **5.5 一节一节上课时：把以前生成过的页面带上，与新章合成一册（可选）**。课是一节一节上的，这一周的课件
   常常只有今天讲的那一章——可以让新的这一章与**以前生成过的那份页面**拼成同一册（拼装器收 `chapters:[…]`，
   老的单章形状照样收），以后再加一章就继续往上并。两条与**写作**直接相关的硬规则（完整四条见契约 `§7.2`）：
   - **关卡号 `lv` 跨章连续**（`0..N-1` 无跳号）：同一个号同时写在正文的 `data-lv`／计数 `data-cnt`、
     题库里**每道题**的 `lv`、以及引擎按 `data-lv` 建的分桶里，三处必须同源。要是各章都从 0 编，
     第一章的题就会**渲进第二章的题区**，而页面不报错（`pit 83`）。
   - **老章的关卡号与题号一个字都不许重算**：作答点 id 就是做题进度的存盘键，给老章改名等于把它那一章的
     进度清零。带过来的章标成"冻结"（`chapters[].chapter.frozen`），新章**只在真会撞车时**才加 `c<章序>-`
     前缀——"在已有的册子上再加一章"是零改名、零搬家的（`pit 84`）。
   带过来的那一份**本身已经是册**，就用它自己的存盘键；否则用**第一份被带的章**的键（册的键与章列表无关，
   见契约 `§7.3`）。**进度存在浏览器本地**：应用内预览 / 双击文件 / 本地服务器三种打开方式互相看不到
   对方的进度，这不是 bug（契约 `§7.5`、`pit 86`）。

6. **校验（不许跳过）**：用 `assets/inject-probe.py` 注入 `verify-probe.js`（+ 有演示就再加 `demo-probe.js`，+ 有陪练就再加 `pet-probe.js`），无头 Edge 跑一遍，逐项核对 `references/build-and-verify.md` 里的十一项。**页面"看起来对"不算数**；演示的读数还要**拿公式手算核对**，并截图看浅色/深色两张。
   **探针管的是"判分逻辑对不对"，管不了"答案本身对不对"**——后者靠第 3 步的审题代理（或自己逐题重算）。陪练要**三种页面都跑**：同目录没图的、有图的、以及"预置了 `petArt:'fish'`、用内置大肥鱼"的各来一次
（第三种最容易漏，而它走的正是"没有图片文件"那条分支）。
7. **收尾**：删掉所有探针副本/截图/临时脚本，只留交付的 HTML（+ 用户放的图片）；告诉用户怎么打开——
   iOS 与安卓最稳的都是"电脑 `python -m http.server 8000` + 手机同 Wi-Fi 访问"，见第四节。

## 三、最致命的六个坑（细节见 `references/pitfalls.md`）

1. **JSON 尾逗号** → 那一段题整段消失，页面**没有任何报错**。题库建议用 Python `json.loads` 预校验、`json.dumps(ensure_ascii=False)` 生成，别手写转义。
   （字段级的错误现在有兜底：引擎会逐题校验并把不合格的题标红跳过 + 告警，见 `references/quiz-engine.md` 第 1.5 节；
   但**尾逗号**这类毁掉整段 JSON 的错还是得靠预校验。）
2. **`<script>` 里引用的 DOM 必须排在脚本之前**。搬动标记（如把陪练块挪到文档末尾）会让 `getElementById` 拿到 `null`，**引擎整段中断、题全没了，仍然不报错**。每个演示/每个独立功能都用 `try{…}catch(e){console.error(…)}` 包住。
3. **探针（以及任何要塞进 script 的文件）正文里不能出现 script 的开/闭标签**——哪怕是注释里举例。HTML 解析器见到结束标签就提前关闭脚本，**整段探针会变成页面上可见的文字、完全不执行**（两个子代理都在这上面白烧了一轮）。所以：**别手工贴探针，用 `assets/inject-probe.py`**（它会先检查并拒绝）。
4. **SVG 的 `<text>` 里不能用 `<sub>/<sup>`**（SVG 不认，会挤成一行）。数字下标 ₀₁₂₃ 可用，字母写成 `μr`。
5. **锚点定位别依赖引号字符**：文件里的引号可能是全角/直引号，直接匹配会失败。用"关键词定位 + `rindex('<h3>')` 往前找标签开头"的写法。
6. **有数据映射的图，刻度坐标也要 JS 算**；`viewBox` 要留余量，**改完必须截图**（裁切、叠字这类问题探针查不出来）。

## 四、手机 / 平板（iOS 与 Android）与离线

页面的主要使用场景是**在手机/平板上看**，两端都要过一遍：

**两端通用**
- 输入框 `font-size` 必须 ≥ **16px**（iOS 聚焦时否则会自动放大整页，安卓某些输入法也会顶版面）。
- 所有 `localStorage` 读写都包 `try/catch`（Safari 在 `file://` 下可能抛 SecurityError；安卓的隐私模式同样）。
- `color-mix()` 前面补一条纯色兜底；`backdrop-filter` 补 `-webkit-` 前缀；`min()/max()/clamp()` 这类较新的 CSS 函数别用来承载"没它就不能看"的布局（不支持时整条声明失效）。
- **不加标签页就不存在"跳转失败"**；页面里所有跳转都用同页锚点。
- 加 `<noscript>` 提示条：题目与演示都靠 JS 生成，用"文件预览"打开会只看到讲解。
- **iPad 上常见的打开方式是「HTML 查看器」这类 App**（系统「文件」App 直接点开是不跑 JS 的预览器，
  只能看到讲解——这不是页面的问题）。这类 App 就是 WKWebView，**渲染没问题**，但有两处宿主能力不能假设：
  ① **`window.confirm/alert` 可能没实现**（没写 `WKUIDelegate` 就永远返回 false）→ 所以**任何确认都做成页内两步确认**，
     别用 `confirm()`；② **`localStorage` 可能被禁**（`file://` 沙盒）→ 探一次"能不能写"，
     不能写就在顶栏写明「进度无法保存」，别让用户以为存上了。同理，**页内跳转一律用锚点**、别依赖宿主允许重载页面
     （「清空重来」已改成逐题复位，不再 `location.reload()`）。
- 单文件交付的好处在这类宿主里最明显：讲解、题库、演示、内置大肥鱼全在文件里。**唯一的外部依赖是同目录的图片**——
  查看器若不给读同目录文件，陪练就不出现，其余功能照常（这正是"没图就什么都不显示 + 一键切内置大肥鱼"的价值）。
- 图与文字都要**同目录**；`<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">` 已经写好，别加 `user-scalable=no`（那是无障碍倒退）。

**iOS 专有**
- 安全区：`viewport-fit=cover` 之后内容会顶到刘海/灵动岛与底部手势条下面，吸顶条与固定元素要用
  `env(safe-area-inset-*)` 让位（骨架页的 `.bar-inner`、`.shell`、`.pet` 都已经这么写了）。
- 长按会弹系统的"存储图像/拷贝"面板，和页面上"长按陪练开菜单"打架 → 陪练形象上必须有
  `-webkit-touch-callout:none`。
- 双击会缩放页面，和"双击陪练换模式"打架 → 陪练形象上 `touch-action:none`。

**Android 专有**
- Chrome 的"字号自动放大"（text autosizing）会把段落字号撑大、把版面顶乱 → `html{-webkit-text-size-adjust:100%;text-size-adjust:100%}`。
- 点按会闪一个灰块 → `-webkit-tap-highlight-color:transparent`。
- 字体栈要带上安卓的中文字体名（`Noto Sans SC` / `Source Han Sans SC` / `Noto Sans CJK SC` / `WenQuanYi Micro Hei`），
  别只写 `PingFang SC`（那是 iOS/macOS 的）。
- 低端机 GPU 弱：整屏 `blur()` 很吃算力，窄屏把模糊半径降下来（骨架页在 `max-width:640px` 里降到了 2px）。
- **打开方式**：安卓不像 iOS 那样能在文件管理器里直接点开 HTML。最稳的是电脑起
  `python -m http.server 8000`，手机同 Wi-Fi 访问 `http://电脑IP:8000/文件名`（两端通用，推荐）；
  或者把 HTML 传到手机后用 Chrome 直接打开（部分文件管理器会拒绝 `file://`，换个 App 即可）。
- 触摸拖动与"页面滚动"要分开：只有陪练形象上 `touch-action:none`，页面别处照常能滚（骨架页就是这么做的）。

**平板专有（iPad / Android 平板，竖屏横屏都要过）**
- **别用手机的断点来判断平板**：640px 那个断点管不到平板（iPad 竖屏 744~1024px 走的是桌面布局），
  所以"手指点不准"这件事要单独用 `@media (pointer:coarse)` 处理：把要按的东西加到 **≥40px 高**
  （骨架页已对顶栏按钮、chips、题卡小按钮、`.btn`、陪练菜单项、滑块拇指…做了）。
  这条媒体查询**必须写在样式表最末**——它要覆盖中段定义过的 `.petmenu button` / `.petpanel input`，
  同权重时靠"后出现者胜"（写前面会被盖掉，实测菜单项只剩 31px）。
- 触屏上"按住不动"会粘住 hover 样式，用 `@media (hover:none)` 把 hover 效果收掉。
- `max-height` 用 `100dvh` 兜一层（iPad Safari 的 `100vh` 比可见区高，弹出层会沉到屏幕外）。
- **横竖屏切换 / 分屏改宽度**时要重新定位开着的弹出层（`resize` + 老 iOS 的 `orientationchange`），
  只重新夹形象是不够的。
- 收尾自查至少要过这几个宽度：**iPad 竖屏 820、iPad 横屏 1180、安卓平板 800、分屏 507、手机 520**，
  每个都看"有没有横向溢出 + 触摸目标够不够大 + 弹出层在不在视口内"（配方见 `references/build-and-verify.md`）。

## 五、陪练（右下角那个形象）

**没形象就什么都不出现。** 引擎不自带任何内置小人；形象只有两条路，右键菜单里随时切：

- **同目录的图片**（默认）：图片名在 `PAGE.petImages` 里配（`pet.png` / `pet.jpg` / `pet.jpeg` / `pet.webp`，也认 `venti.*`），
  命中就同时当右下角圆形头像 + 全页淡背景。**图片名别写死成某一章的文件名**（坑清单第 17 条的延伸）。
- **内置「大肥鱼」**：素材来自 `1190fasheqi/dafeiyu-pet`（MIT），已量化后以 data URI 嵌进引擎，
  页面不用带任何图文件就能有陪练；原图、许可、出处、以及"想换掉该怎么办"都在 `third-party/dafeiyu-pet/README.md`。
  引擎里 `FISH` 常量的正上方还**内联了一份 MIT 许可原文**——那是故意放的，别删：引擎会整段复制进
  每一张生成的页面，只有跟着页面走才算"许可随副本分发"。
  **这是唯一一份第三方美术**——别的形象一律"用户自己放图，我只接线"，不要去网上抓官方美术。

一个形象都没有时：右下角保持空无一物（`display:none`、占位 0px），顶部开关显示「没放图」，
点它给两条路（换成内置大肥鱼 / 怎么放自己的图）。交互是：**拖走记位置 · 单击说话 · 双击换模式 ·
右键（手机上长按）菜单**；台词**每一句都能被用户自己的文本顶掉**（`pet-lines.js` 或页面内联 JSON 块）。

完整规范（形象来源表、交互约定、台词键位表与四种注入方式、容错、验收清单）见 `references/pet-guide.md`。

**用户已明确：陪练与背景图"到处都在"，每一页都默认启用，不要做"逐页问要不要"的配置**
（2026-10-13 确认）。页面上那个开/关按钮是给用户临时收起来的交互，不是配置项，别删也别改成默认关。
图片与形象都是**异步**的（实测 1~2 秒），页外想确认生效没有，用 `pet-probe.js` / `verify-probe.js` 的轮询，别用固定延时。

## 六、资产

**三份"页面级"资产是同一套东西的不同呈现**：`page-skeleton.html` 已经**内联**了 `practice.css` 与 `quiz-engine.js`。两个同步器管两个方向，别用错：

- **改的是 `assets/` 原文**（推荐，因为 `quiz-engine.js` 才是引擎的源头）→ 跑 `assets/sync-skeleton.py`
  （默认只检查两边有没有走散、`--write` 才写进骨架）；
- **改的是某个跑通的章节页**（在页面里直接改内联引擎）→ 跑 `assets/refresh-assets.py` 从页面反抽回资产。

新章直接复制骨架页改就行；`quiz-engine.js` / `practice.css` 也是给你查阅与抽取用的。**两边一旦走散，
症状是"改了资产、新章却还是老引擎"**，所以改完一定要跑一次同步器看一眼。

## 七、新章上手清单（照做即可）

```bash
D="/path/to/your/project"
SK="$D/.claude/skills/interactive-study-guide"
# 0. （只在改过 skill 自己的资产时）确认骨架内联副本没走散
python "$SK/assets/sync-skeleton.py"            # 不一致就加 --write
# 1. 复制骨架 -> 这一章的页面；改标题、章号、题库、正文、PAGE.key
cp "$SK/assets/page-skeleton.html" "$D/chNN-...-practice.html"
# 2. （若要与手册合体）改 merge-interleave.py 顶部的 CFG，然后：
python "$SK/assets/merge-interleave.py"
# 3. 注入探针并跑（每次换一个 user-data-dir；陪练要"有图/没图"各跑一次）
python "$SK/assets/inject-probe.py" "$D/chNN-...-full.html" verify-probe.js demo-probe.js pet-probe.js
E="/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"      # 直接写 msedge 多半不在 PATH 里
T="C:\\Users\\<你>\\AppData\\Local\\Temp"                          # %TEMP% 是 cmd 语法，bash 不展开
"$E" --headless=new --disable-gpu --no-sandbox --user-data-dir="$T\\p1" \
     --virtual-time-budget=22000 --dump-dom "file:///<上面输出的 _probe_*.html>" | grep '<title>'
# 4. 截图看浅色/深色（探针查不出叠字与裁切）
# 5. 删掉探针副本与截图，只留交付的 HTML（+ 用户放的图片）
```

**单节迷你页**（只想给一小节配练习）：同样从骨架起步，规格可以放宽——**≥6 个作答点**、演示可选（这一节不适合拖就别硬凑）、结算区保留（引擎引用了 `#result` 里的元素，删了会报错）但可以把「接下来做什么」的文案改短。引擎的评级阈值是按**比例**算的，页小也适用。

**讲的风格**（四段式：大白话要解决什么 → 核心公式 → 公式为什么长这样 → 单独列易错点；公式给记忆锚；
   记忆锚与易错点是重点）是这个 skill 的既定写法，别改。
